# 拼豆工坊 V1 产品需求文档

## 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 拼豆工坊 |
| 产品类型 | PC Web 图片转拼豆工具 |
| 当前版本 | V1 |
| 目标用户 | 普通拼豆爱好者 |
| 产品形态 | V1 仅开发 PC 网站 |
| 注册要求 | 免费使用，无需注册 |
| 官方拼豆色卡 | MARD 291 色完整色卡 |

## 1. 产品定位与目标

### 1.1 核心价值

拼豆工坊帮助用户将一张普通图片转换为可以真正用于制作拼豆作品的图纸。

产品不是单纯的“图片像素化工具”，而是形成完整的制作闭环：

> 上传图片 → 裁剪 → 设置尺寸 → 生成拼豆图 → 轻量修改 → 查看真实拼豆色号及用量 → 导出可以实际制作的图纸

### 1.2 V1 核心目标

1. 图片能够稳定生成基本可用的拼豆图。
2. 用户能够修改生成结果中不满意的部分。
3. 所有颜色对应真实拼豆色卡。
4. 用户能够知道每种拼豆需要多少颗。
5. 用户能够导出真正可以照着制作的 PNG / PDF 图纸。
6. 优先完成基本功能并上线，不追求一次把高级算法做到极致。

## 2. V1 用户主流程

### 2.1 完整流程

首页 → 上传图片 → 裁剪图片 → 设置作品宽度 → 系统自动计算高度 → 确认生成模式 → 生成拼豆图 → 进入结果页 / 编辑器 → 局部修改 → 管理颜色 → 查看材料统计 → 导出 PNG 或 PDF

### 2.2 返回裁剪时的数据保留

用户从结果页返回重新裁剪时，系统必须保留：

- 原始上传图片
- 上一次裁剪范围
- 上一次宽度
- 上一次生成模式

不得要求用户重新上传图片。

### 2.3 当前作品恢复

V1 使用 IndexedDB 保存当前工作会话。

用户在编辑器或生成流程中刷新浏览器后，可以恢复当前作品。恢复内容至少包括：

- 原始图片或可恢复的本地图片数据
- 裁剪信息
- 作品宽度
- 自动计算后的高度
- 生成模式
- MARD 291 色色卡版本
- 当前拼豆矩阵
- 作品名称
- 恢复当前作品所需的其他必要数据

不需要保存：

- Hover 状态
- 鼠标位置
- 临时弹窗
- 临时预览
- 其他瞬时 UI 状态

保存的是作品状态，不是界面瞬时状态。

用户主动上传并开始新的图片项目时，新的当前项目可以替换当前本地工作会话。

V1 不提供：

- 作品库
- 历史项目列表
- 云同步
- 用户账号

## 3. 首页

### 3.1 页面目标

让第一次进入网站的用户快速理解产品，并立即上传图片。

### 3.2 页面内容

核心 CTA：**上传图片**

主标题方向：

> 把你的图片，变成可以直接制作的拼豆图纸

副标题应突出：

- 图片自动转换
- MARD 291 色拼豆色卡
- 拼豆图纸
- 用豆数量统计

首页可以包含：

- Logo
- 简单导航
- 产品介绍
- 原图 → 拼豆效果案例
- 三步使用说明

三步说明：

1. 上传图片
2. 调整尺寸
3. 下载图纸

首页不提供“试试看示例”功能。

## 4. 图片上传

上传不需要单独设计一个完整页面，用户可以在首页直接上传。

### 4.1 支持方式

- 点击选择本地图片
- 拖拽图片
- Ctrl + V 粘贴图片

### 4.2 支持格式

- JPG
- PNG
- WEBP

### 4.3 异常处理

| 情况 | 产品规则 |
| --- | --- |
| 图片分辨率较低 | 提示可能影响生成质量，但允许继续 |
| 图片非常大 | 系统自动进行必要预处理 |
| 格式不支持 | 明确提示支持 JPG / PNG / WEBP |
| 宽高比异常 | 不禁止上传，在后续裁剪阶段处理 |

### 4.4 作品名称初始值

如果通过文件上传，默认作品名称使用原始文件名去掉扩展名。

例如：

> 我的猫咪.jpg → 我的猫咪

如果图片来自 Ctrl + V 粘贴且没有原始文件名，默认作品名称为“未命名作品”。

用户不需要在生成前填写作品名称，可以在结果页右侧作品信息中修改作品名称。

## 5. 裁剪与生成设置

页面采用“左侧大面积图片裁剪区域 + 右侧生成参数面板”的布局。

### 5.1 图片裁剪

用户上传成功后必须先进入裁剪。

默认使用整张图片。

支持：

- 移动裁剪区域
- 自由改变裁剪框尺寸
- 自由改变裁剪比例
- 图片缩放
- 左旋转 90°
- 右旋转 90°

裁剪比例不锁定。后续拼豆高度必须根据用户最终确认的裁剪区域宽高比自动计算。

## 6. 拼豆尺寸与规格

### 6.1 作品尺寸设置

用户只允许设置拼豆作品宽度，不得同时让用户自定义宽度和高度，系统自动计算高度。

计算规则：

> 高度 = round（宽度 ÷ 裁剪区域宽高比）

示例：

- 裁剪区域比例为 4:3
- 用户输入宽度为 64 颗
- 系统自动得到高度 48 颗

允许设置的拼豆作品宽度范围为 **8～256 颗**，用户不能输入范围外的宽度。

默认宽度为 **64 颗**。

提供推荐快捷值：

- 32
- 48
- 64
- 96

同时允许自定义宽度。系统实时显示：

- 最终豆数尺寸
- 实际成品尺寸

高度继续根据用户最终确认的裁剪区域宽高比自动计算。若自动计算后的高度导致作品比例异常或规模很大，系统优先提示风险；V1 暂不定义额外的总格数性能上限。

### 6.2 拼豆规格

V1 默认且固定使用 **2.6mm 拼豆**，不提供其他规格选择。

实际尺寸计算：

- 成品宽度 = 横向豆数 × 2.6mm
- 成品高度 = 纵向豆数 × 2.6mm

示例：64 × 48 颗约等于 16.64cm × 12.48cm。

界面可以进行合理的小数格式化显示。

## 7. 拼豆色卡

### 7.1 色卡范围

V1 使用 **MARD 291 色完整拼豆色卡**。

本文后续所有“291 色”均指 MARD 291 色。

MARD 291 色表示系统允许使用的真实拼豆颜色全集，并不意味着每张作品必须使用 291 种颜色。每张作品的实际使用颜色数量由图片决定。

所有最终拼豆颜色必须来源于 MARD 291 色中的唯一 `colorId`，包括：

- 自动生成
- 高清还原模式
- 拼豆优化模式
- 单颗改色
- 画笔
- 填充
- 全局颜色替换
- 材料统计
- PNG
- PDF

V1 不允许用户输入任意 RGB、HEX 或自定义屏幕颜色作为最终拼豆颜色。

### 7.2 色卡数据规则

- 每种颜色必须存在唯一 `colorId`。
- 色号是颜色的核心唯一标识。
- 中文颜色名称只是辅助信息。
- 生成算法、编辑器、材料统计、PNG 和 PDF 必须使用同一套 MARD 291 色数据源。

## 8. 生成模式

V1 提供两种生成模式。

### 8.1 拼豆优化模式

拼豆优化模式为默认模式。用户上传并完成设置后，默认生成拼豆优化模式。

产品目标是在保持原图基本识别度的同时，让生成结果更适合实际拼豆制作。

重点：

- 适度减少碎色
- 保持主要轮廓
- 适度合并无意义的相近颜色
- 降低不必要的背景纹理
- 保证作品整体更容易实际制作

### 8.2 高清还原模式

用户可以主动选择高清还原模式。目标是在当前作品尺寸及 MARD 291 色限制范围内，尽可能保留原图的：

- 颜色
- 明暗
- 局部细节
- 色彩层次

高清还原模式仍然只能使用 MARD 291 色中的颜色。

### 8.3 模式生成规则

- 系统不能同时生成两个版本让用户选择。
- 默认只生成拼豆优化模式。
- 用户主动切换高清还原后，必须重新基于原始裁剪图片生成。
- 模式切换不得基于当前已经生成的拼豆图进行二次转换。

## 9. 拼豆优化模式 V1 算法产品规则

V1 不针对人像、宠物、动漫、插画、风景分别设计专属生成策略，第一版统一使用一套基础规则。

优先完成基本功能并上线，后续持续优化算法。

基础处理流程：

> 裁剪图片 → 按目标尺寸进行采样 → 颜色处理 → 映射至 MARD 291 色 → 基础轮廓优化 → 基础碎色优化 → 基础背景简化 → 输出拼豆矩阵

### 9.1 碎色优化

不能简单按照“少于 X 颗就删除”进行处理。

核心原则：

> 小 + 相近 + 孤立 + 非关键视觉信息 → 倾向合并

基础候选规则：

| 连续色块大小 | 默认处理倾向 |
| --- | --- |
| 1 颗 | 强合并候选 |
| 2 颗 | 合并候选 |
| 3 颗 | 根据周围情况判断 |
| 4～6 颗 | 通常偏向保留 |
| 7 颗以上 | 默认保留 |

以下情况提高保留概率：

- 与周围颜色对比明显
- 位于重要结构边缘
- 对整体形状有帮助
- 是明显的小型视觉特征
- 是规律性图案的一部分

以下情况提高合并概率：

- 与周围主色非常接近
- 位于大面积相近色块内部
- 属于随机照片纹理
- 属于孤立杂点
- 全图使用量极低且存在高度相似替代色

V1 处理原则偏保守：宁愿暂时多保留少量杂色，也不要激进删除可能影响识别度的重要豆。

### 9.2 轮廓强化

核心原则是强化结构边界，不是给所有物体加黑色描边。

优先保护：

1. 主要外轮廓
2. 大型内部结构边界
3. 明显形状转折

弱化：

- 背景纹理
- 无意义细线
- 细碎照片纹理

优先通过调整 MARD 291 色映射结果，让重要边界两侧拥有足够视觉差异。

不得默认给所有轮廓增加黑色描边。轮廓色应尽量来自符合原图色调的真实色卡颜色。允许轮廓局部存在，不强制整个物体闭合描边。

### 9.3 背景简化

V1 只做基础背景简化，目标是：

- 减少大面积背景中的相近碎色
- 保留背景主要色块
- 降低无意义照片纹理

不能自动删除普通背景。

普通白色背景必须作为真实白色拼豆处理，不能自动认为是透明区域。

### 9.4 透明与空白

Alpha = 0：转换为拼豆矩阵 `EMPTY`。

Alpha > 0：不视为空白，不能转换为 `EMPTY`。

Alpha 在 0 和 255 之间的半透明像素：先与白色背景进行 Alpha 合成，再将合成后的颜色映射到 MARD 291 色。

因此：

- 完全透明 = `EMPTY`
- 半透明 ≠ `EMPTY`
- 普通白色 ≠ `EMPTY`，必须对应 MARD 色卡中的真实白色拼豆 `colorId`

`EMPTY` 和白色拼豆必须是两个完全不同的状态。

空白只能来自：

1. 原始图片真实透明通道
2. 用户使用橡皮擦主动删除

算法不能为了减少豆数而自动把正常图片区域变为空白。

## 10. 高清还原模式规则

相比拼豆优化模式，高清还原模式应：

- 减少碎色合并
- 减少相近颜色主动合并
- 减少人为轮廓强化
- 保留更多明暗变化
- 保留更多实际使用颜色

但所有最终颜色依然必须属于 MARD 291 色色卡。

## 11. 结果页 / 编辑器

### 11.1 整体布局

PC 编辑页采用三栏布局：

- 左侧：编辑工具
- 中间：拼豆主画布
- 右侧：作品信息、颜色管理和输出

中间主画布占最大面积。

### 11.2 左侧编辑工具

V1 核心工具如下。

基础工具：

- 选择
- 撤销
- 重做

编辑工具：

- 单颗改色
- 画笔
- 填充
- 吸管
- 橡皮擦

辅助显示：

- 网格
- 色号
- 颜色高亮

#### 单颗改色

点击一个格子后，打开统一 MARD 291 色选色组件。

#### 画笔

V1 画笔大小固定为 1 颗。

#### 填充

只影响与点击位置连续连接且颜色相同的区域，不得默认替换整张作品所有相同颜色。

#### 吸管

从当前拼豆矩阵中获取一个 `colorId`，该颜色自动成为当前活动颜色。

#### 橡皮擦

将一个拼豆格从颜色变为 `EMPTY`。白色拼豆擦除后必须变成 `EMPTY`，而不是另一种白色状态。

### 11.3 当前活动颜色

整个编辑器只存在一个当前活动颜色。左侧工具与右侧颜色管理必须共享这一状态。

示例：

- 右侧选择 A25，左侧画笔自动使用 A25。
- 使用吸管得到 B13，右侧颜色管理自动定位并选中 B13。

不得存在互相不同步的两套颜色选择状态。

## 12. 主画布与辅助显示

### 12.1 主画布能力

V1 必须支持：

- 自动适应窗口
- 鼠标滚轮缩放
- 拖动画布
- 100% 查看
- 回到中心
- 单颗网格
- 每 10 格辅助粗线
- 行列编号
- 色号显示
- 鼠标悬停反馈
- 编辑预览
- 原图快速对比
- 迷你导航图

建议缩放范围为 10%～800%，缩放应尽量围绕鼠标所在位置。

拖动画布支持：

- 空格 + 鼠标左键
- 鼠标中键

### 12.2 网格

网格视觉强度随缩放等级变化：

- 低倍率：可以弱化甚至隐藏单颗细网格
- 中高倍率：显示单颗网格
- 每 10 格：显示一级更明显的辅助线

### 12.3 色号显示

色号显示默认关闭，用户可以开启。

当画面缩放倍率不足以清晰显示文字时，不应强行塞入色号文字。放大到合适倍率后，每颗豆中央显示对应色号。文字颜色应根据底色明暗自动调整，保证可读性。

### 12.4 行列坐标

- 画布顶部显示列编号。
- 画布左侧显示行编号。

行列坐标用于实际拼豆制作时定位。

### 12.5 原图快速对比

V1 使用简单方案：用户按住“原图”按钮时显示裁剪后的原始图片，松开后返回拼豆图。

V1 暂不开发复杂左右对比滑杆。

### 12.6 迷你导航图

V1 必须包含迷你导航图，位置在主画布右下角。

功能：

- 显示完整作品缩略图
- 显示当前主画布视野范围
- 点击缩略图某个位置快速跳转
- 拖动视野框移动主画布
- 编辑后实时同步
- 颜色高亮时同步展示

迷你导航图可以折叠。

## 13. 结果页右侧信息与颜色管理

### 13.1 作品信息

显示：

- 作品名称
- 拼豆豆数尺寸
- 拼豆规格 2.6mm
- 实际成品尺寸
- 总拼豆数量
- 实际使用颜色数量
- 当前生成模式

### 13.2 生成模式切换

结果页允许在“拼豆优化”和“高清还原”之间切换。

切换必须基于原始裁剪图片重新生成。

如果用户已经进行手动编辑，必须提示：

> 切换模式会重新生成作品，当前手动修改会被清除。

提供：

- 取消
- 重新生成

### 13.3 颜色管理

顶部展示：

- 实际使用颜色数 / 291
- 总豆数

颜色搜索支持：

- 色号
- 颜色名称

排序支持：

- 按使用数量
- 按色号

默认按使用数量从高到低。

每条颜色显示：

- 色块
- 色号
- 颜色名称
- 使用数量
- 占总豆数比例

### 13.4 颜色高亮

用户点击一个颜色后，中间主画布突出该 `colorId` 对应的所有豆，其他颜色降低视觉权重。用户可以退出高亮。

### 13.5 全局颜色替换

流程：

1. 用户选择替换某个颜色。
2. 打开统一 MARD 291 色选择组件。
3. 用户选择目标颜色。
4. 主画布先实时预览。
5. 显示原色 → 新色，以及将影响多少颗拼豆。
6. 用户确认后才正式执行。

全局替换必须支持撤销 / 重做。

### 13.6 颜色优化提示

V1 可以包含基础优化提示：

- 相近颜色合并建议
- 使用数量非常少的颜色提示

示例：

- “发现 4 组相近颜色”
- “6 种颜色使用量低于 10 颗”

用户可以逐组确认。不得在用户不知情的情况下自动大规模修改已经生成好的作品。

## 14. MARD 291 色完整选色组件

所有选颜色操作共用同一组件。

V1 必须支持：

- 搜索色号
- 搜索颜色名称
- 按色系浏览
- 按色号浏览
- 推荐相近颜色
- 当前作品已使用颜色
- 最近使用颜色
- 颜色详情
- 当前作品使用数量
- 全局替换预览

默认浏览方式为按色系浏览。

每个色块至少显示：

- 色块
- 色号

悬停后显示详细信息。

颜色详情至少包含：

- 色号
- 名称
- 大色块预览
- 当前作品使用数量

屏幕颜色只是预览。产品后续应考虑提示：不同显示设备可能存在色差，请以实际拼豆颜色为准。

## 15. 材料统计

右侧颜色列表已经显示每种颜色用量，因此不需要再重复一份完全一样的统计列表。

提供“查看完整材料清单”。完整清单至少包含：

- 色号
- 名称
- 实际使用数量
- 建议准备数量

默认损耗为 **5%**。建议准备数量基于实际数量增加约 5%。

## 17. PDF 制作图纸

PDF 是完整制作文件。

### 17.1 默认结构

#### 总览页

包含：

- 作品名称
- 完整效果图
- 豆数尺寸
- 2.6mm 规格
- 实际成品尺寸
- 使用颜色数量
- 总豆数

#### 分页制作图

每颗豆显示对应颜色和色号，包含：

- 网格
- 行列编号
- 每 10 格粗线
- 当前分页位置
- 页码
- 当前页面对应整幅作品中的位置缩略图

#### 材料清单页

包含：

- 色号
- 名称
- 使用数量
- 建议准备数量

### 17.2 PDF 分页规则

不能固定为 40 × 40。

PDF 默认使用 A4 纸张，页边距为 10mm，页面方向自动选择横向或纵向。

单颗拼豆格子的目标打印尺寸约为 6mm，合理目标区间为约 5～7mm。色号字号根据实际单格尺寸自动计算，以清晰可读为优先。

默认开启：

- 网格
- 行列坐标
- 每 10 格辅助粗线
- 色号
- 材料清单

默认模式为彩色，材料损耗为 5%。

自动分页算法优先级为：

1. 色号清晰可读
2. 单颗格子具有足够打印尺寸
3. 在保证可读性的基础上尽量减少分页数量

不得为了减少页数而把格子压缩到明显影响色号阅读。

自动分页主要考虑：

- A4
- 页面方向
- 有效打印区域
- 单格可读性
- 总分页数量

例如，系统可能推荐 32 × 40 颗 / 页。

用户允许手动调整每页横向和纵向格数。修改后实时显示预计生成页数。

用户手动提高每页格数时，如果预计导致格子小于合理打印尺寸或色号可读性下降，系统显示警告，但允许用户继续导出。

### 17.3 PDF 设置

V1 支持：

- A4
- 自动判断横向 / 纵向
- 自动推荐分页
- 用户自定义分页格数

- 色号开关
- 行列坐标
- 10 格辅助线
- 材料清单
- 默认 5% 损耗

V1 黑白模式依赖清晰色号进行识别，暂不开发复杂的“每种颜色对应不同图形符号”系统。

## 21. V1 验收目标

### 21.1 用户端到端验收流程

一个第一次使用拼豆工坊的普通用户，必须可以独立完成：

打开网站 → 上传一张图片 → 完成裁剪 → 设置作品宽度 → 自动得到高度 → 生成拼豆图 → 查看完整作品 → 修改任意一颗拼豆颜色 → 删除任意一颗拼豆 → 替换整幅作品中的某一种颜色 → 查看每个色号需要多少颗 → 导出可以直接查看制作的 PNG → 导出可以打印使用的分页 PDF

### 21.2 算法与数据一致性验收

算法 V1 的验收原则是：**稳定可用优先于高级智能。**

要求：

1. 拼豆优化模式不能出现大量明显随机杂色。
2. 高清还原模式应该明显比拼豆优化模式保留更多局部色彩和细节。
3. 两种模式应有肉眼可感知的差异。
4. 所有最终颜色必须属于统一 MARD 291 色色卡。
5. 编辑器、材料统计、PNG、PDF 中的色号和数量必须保持一致。
6. `EMPTY` 与白色拼豆必须始终严格区分。
7. V1 优先完成基本功能并上线，复杂算法在上线后持续迭代。
