# TASK-096 IndexedDB 失败降级记录

日期：2026-10-12

## 测试覆盖

- Unit：模拟 `IDBFactory.open()` 安全错误、恢复读取失败及已有合法内存 Project；断言存储错误与生成错误分离，恢复失败不水合部分/损坏数据，也不覆盖现有内存 Project。
- Component：持久化失败时 Editor 内容仍显示，同时出现明确未保存提示和“重试保存”入口。
- Chromium E2E：使用真实浏览器 IndexedDB，测试打开失败后重试、损坏记录的显式处理和新作品建立、写入配额失败与重试。
- 配额用例通过在真实 IDB `readwrite` 写入边界注入 `QuotaExceededError` 模拟，不通过填满用户浏览器磁盘制造自然配额耗尽。

## 结果

1. **打开失败**：浏览器存储打开被模拟拒绝时应用进入明确恢复错误界面，不白屏；错误文案说明是本地存储不可用而不是误报数据损坏。存储恢复后重试成功，用户可上传、生成并写入新作品。
2. **配额/写入失败**：编辑后的内存 Grid 与 revision 保持最新；既有 IndexedDB 快照仍完整保留旧 revision，没有部分覆盖。关闭故障注入后点击重试，最新 Project/Grid 成功落盘，恢复正常保存状态。
3. **损坏记录**：启动恢复拒绝 malformed Grid，不渲染 Editor、不触发生成；本地记录在用户明确确认前保留。确认清除后新作品可正常生成并成为当前会话记录。
4. **失败分类**：IndexedDB 打开错误、恢复数据错误、保存失败提示均与 Worker 生成失败分开；错误不自动删除本地会话。

## 安全边界

- IndexedDB 事务、active-session schema、Project/Grid schema 均未修改。
- 不引入 localStorage 备份、自动删除/修复损坏记录或云同步。
- 本地内存编辑可以继续；保存失败明确提示刷新可能丢失尚未持久化的更改，并允许重试。
- 受控的配额注入证明事务失败时旧快照安全，不代表能测得各浏览器实际可用存储空间。目标浏览器自然配额/隐私模式仍可在兼容性阶段另行观察。
