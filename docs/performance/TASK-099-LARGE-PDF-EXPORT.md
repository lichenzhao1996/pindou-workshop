# TASK-099 大型作品 PDF 分页与导出性能记录

日期：2026-10-12

## 可复现条件

- 执行：`npm run test:e2e -- tests/e2e/task097-099.large-exports.spec.ts --workers=1 --reporter=json`。
- 本地 production preview，真实 Chromium、真实 generation Worker、正式 Export Snapshot、正式 PDF 下载及 `pdfjs-dist` 解析。
- 环境：Windows 10 x64，Headless Chromium 151.0.7922.34，`navigator.hardwareConcurrency=12`。
- 确定性样本：256×192 Grid（49,152 格），含 EMPTY、真实白色及多种 MARD 颜色；使用正式默认 A4 自动分页，并另测 128×96 格/页的手动单色模式。
- 导出耗时从点击 PDF 按钮到下载事件，含导出与下载准备；每个实际文件通过 `%PDF-` 签名和解析器验证页数、页面尺寸、文本与分页范围。

## 实测结果

| 模式 | 总页数（总览 + 图纸 + 材料） | 图纸页数 | 文件大小 | 点击至下载 |
| --- | ---: | ---: | ---: | ---: |
| 自动分页、彩色，第 1 次 | 47 | 45 | 21,336,314 B（约 20.35 MiB） | 7,923.46 ms |
| 自动分页、彩色，第 2 次 | 47 | 45 | 21,336,314 B（约 20.35 MiB） | 8,029.38 ms |
| 手动 128×96、黑白 | 6 | 4 | 21,575,859 B（约 20.58 MiB） | 8,126.61 ms |

自动方案为纵向，9 页格宽 × 5 页格高，每页目标单格尺寸约 6.05 mm；PDF 解析出的 A4 页面为约 595.28×841.89 pt。手动样本为横向，布局计算单格约 1.6146 mm，已有 PDF 可读性警告显示且导出仍可执行；4 张制作图与总览、材料页均保留。

两个模式都逐页读取实际 PDF 的 0-based 半开 Grid 范围，并与正式分页计划逐项比对；对 256×192 的全部 49,152 格做覆盖计数，确认每格恰好出现一次、没有遗漏或重复。PDF 文本包含作品尺寸、2.6mm 规格、实际总豆数、颜色数、MARD 色号、页码及材料清单。导出前后 Project/Grid hash、revision、updatedAt 和 History 摘要相等；对象 URL 均撤销，下载锚点移除。

浏览器 PDF.js 在中文字体解析时输出 `UnknownErrorException: Ensure that the standardFontDataUrl API parameter is provided` 及字体 glyph 空间提示；解析仍成功，中文任务文本及正式色号断言均通过。该提示来自测试解析器缺少标准字体资源，不代表应用 PDF 未嵌入项目中文字体；仍应在目标 PDF 阅读器/实体打印环境进行人工观感验收。

## 内存、失败与范围

- 此 Chromium 环境没有可靠的浏览器进程峰值 RSS/原生图形内存数据，未使用 JS heap 冒充 RSS。
- Grid 为 `Uint16Array`，本样本 payload 98,304 B；PDF 导出另有快照副本及分页、Canvas/PNG 缩略图、PDF 文档对象和编码缓冲区。实际峰值未测得。
- PDF thumbnail 编码后释放其临时 Canvas backing store；编码 null/抛错及 context 不可用路径安全失败并释放资源，定向单测覆盖。实际导出文件能够解析，页面内容未通过减格、删标注或减少材料信息来换取性能。
- 大于 49,152 格的 PDF 未在本批实测。256×1,280 已有生成与刷新恢复数据，但不等于该尺寸 PDF 已验证。
- 未连接打印机，纸张物理尺寸及真实打印缩放为“待人工实物验收”；PDF 页面尺寸与文件解析自动验证已完成。

## 结论

本机 Chromium 上，49,152 格作品的自动彩色 47 页 PDF 和手动密集黑白 6 页 PDF 均成功下载、解析并完整覆盖 Grid。性能数字是该机器的一次串行 E2E 中的重复样本，不是低端设备承诺。PDF 的文件体积约 20–21 MiB、导出约 7.9–8.1 秒；更大格数、低内存设备及物理打印仍需后续目标环境验证。没有减少正式制作图内容，没有改变 V1 格数规则。
