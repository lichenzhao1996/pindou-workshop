## 使用规则

- 本文只定义开发顺序、任务边界和验收方式，不替代 PRD 或技术设计，也不改变产品规则。
- 每个任务都应在开始前重新阅读 `AGENTS.md` 和本任务涉及的 PRD / TECHNICAL-DESIGN 章节，并检查当前实现与测试。
- 默认由一个产品负责人和 Codex 串行开发、串行验收。只有文档明确标注“可并行”的任务，才考虑并行。
- `P0` 为 V1 主流程或上线门禁必须完成；`P1` 为不阻塞完整制作闭环、可在上线前后安排的增强能力。PRD 已明确为 V1 必须完成的能力不得降为 P1。
- 每个任务的“完成定义”都必须满足：范围内功能实现、对应测试通过、现有测试无回归、构建通过、没有顺手加入范围外功能。
- 任务中的目录是预计目录，不要求在本文件创建时预先创建具体业务文件。

## 推荐开发主链路

工程基础 → Project / Grid → MARD 291 色 Palette → 首页与图片输入 → 裁剪与生成设置 → 基础图片流水线 → 高清还原 → 拼豆优化 → 编辑器画布 → 统一选色器 → 编辑工具 → 迷你导航图 → 颜色管理 → 作品信息与 IndexedDB 恢复 → 材料统计 → PNG → PDF → 颜色优化建议 → E2E → 性能与上线准备 → V1 上线验收

### 可并行但默认不并行的任务组

- TASK-006、TASK-007 在 TASK-001 完成后可与 TASK-002～TASK-005 并行；单人协作默认仍串行，以减少配置冲突。
- TASK-013～TASK-018（Palette）与 TASK-008～TASK-012（Project / Grid）在接口约定稳定后可以并行；默认先完成 Project / Grid，再接入 Palette。
- TASK-019～TASK-023（首页与输入）与 TASK-043～TASK-050（编辑器画布）理论上可并行，但都依赖工程基础，默认不并行。
- TASK-077～TASK-079（PNG）与 TASK-080～TASK-087（PDF）在 Export Snapshot 接口稳定后可以并行。
- TASK-092～TASK-098 是验证阶段，可按浏览器或输出类型分工，但默认按顺序执行并集中记录结果。

### 必须串行的关键链路

Project / Grid → Palette → 生成流水线 → Editor Project 状态 → 统计 / 导出 Snapshot → PNG / PDF → E2E → 性能门禁 → 上线验收。

## Phase 0：工程基础

### TASK-001：初始化 Vue 3 + TypeScript + Vite 工程（P0）

**目标**

建立可启动、可构建的 Vue 3 PC Web 空仓库基础，不实现任何产品页面或业务功能。

**前置依赖**

无。

**本次范围**

- 初始化 Vue 3、TypeScript、Vite 工程。
- 建立开发、预览、生产构建脚本。
- 开启 TypeScript 严格检查所需的最小配置。

**不在本次范围**

- 首页、上传、裁剪、编辑器或任何业务页面。
- MARD 色卡数据、算法、后端和账号能力。

**涉及模块**

`package.json`、`vite.config.*`、`tsconfig.*`、`src/`、`index.html`。

**产品规则**

V1 仅开发 PC Web；遵守 PRD §1 和 TECHNICAL-DESIGN §3。

**技术要求**

- 只使用确认的 Vue 3 + TypeScript + Vite 技术栈。
- 保持纯前端和静态构建方向。
- 不在初始化中引入未确认的框架或服务端。

**验收标准**

1. 开发命令可以启动基础 Vue 应用。
2. 生产构建成功生成静态产物。
3. TypeScript 检查通过。
4. 仓库中没有业务页面或业务逻辑实现。

**自动化测试要求**

- 单元测试：暂不需要，尚无领域逻辑。
- Vue 组件测试：暂不需要。
- E2E：需要最小启动 / 构建冒烟脚本，验证应用可打开。

**手动验收建议**

启动开发服务器访问根地址，再执行生产构建并检查 `dist/` 产物存在。

**完成定义**

工程基础可启动、可构建、类型检查通过，且没有超出本任务范围的产品代码。

### TASK-009：实现 Grid、Uint16Array 与 EMPTY 基础结构（P0）

**目标**

建立行优先的一维 `Uint16Array` Grid，并严格区分 `EMPTY` 与 MARD 白色。

**前置依赖**

TASK-008。

**本次范围**

- 定义 `EMPTY = 0`。
- 实现 Grid 创建、宽高、cells 和 palette index 基础结构。
- 定义 0 与 1～291 的合法值域。

**不在本次范围**

- 不录入 MARD 数据。
- 不实现画布、统计、编辑器或颜色选择。

**涉及模块**

`src/domain/project/grid.ts`、`src/domain/project/constants.ts`。

**产品规则**

遵守 PRD §9.4、§18：真实透明和橡皮擦才可产生 EMPTY，白色拼豆不能当作 EMPTY。

**技术要求**

- 使用一维行优先 `Uint16Array`。
- `EMPTY=0`；Palette index 1～291 表示 MARD 291 色。
- 不把 RGB / HEX 写入 Grid。

**验收标准**

1. 创建指定宽高 Grid，cells 长度等于 `width × height`。
2. 初始格子为 EMPTY。
3. 0 与任意合法白色 palette index 可被区分。
4. 非法值域不能静默写入。

**自动化测试要求**

- 单元测试：必须覆盖长度、初始 EMPTY、值域和白色不等于 EMPTY。
- Vue 组件测试：不需要。
- E2E：不需要。

**手动验收建议**

通过测试 fixture 查看初始 Grid，确认空格不是渲染色卡中的白色值。

**完成定义**

Grid 基础结构和 EMPTY 语义可独立测试，测试通过。

### TASK-010：实现 Grid 读写、坐标转换与 revision 更新（P0）

**目标**

提供所有编辑和渲染都复用的 Grid 读取、修改和不可变更新入口。

**前置依赖**

TASK-009。

**本次范围**

- 实现 index 与 row / column 的转换。
- 实现单格读取、合法性校验和批量操作接口。
- 实现 `applyGridOperation` 的不可变 cells 替换和 revision 增加。

**不在本次范围**

- 不实现具体 Vue 工具按钮、Canvas 命中测试或 Undo UI。
- 不实现自动生成算法。

**涉及模块**

`src/domain/project/grid.ts`、`src/domain/project/operations.ts`。

**产品规则**

所有编辑工具最终修改同一份 Grid；PRD §11 的单颗改色、填充、橡皮擦和全局替换不得各自维护数据。

**技术要求**

- 不原地修改当前快照。
- 每次实际修改增加 revision；无变化操作不制造虚假变更。

**验收标准**

1. row / column 与 index 转换可逆。
2. 单格和批量写入只改变目标格。
3. 新 Project 使用新 cells 引用并增加 revision。
4. 非法坐标和值被拒绝。

**自动化测试要求**

- 单元测试：正常、边界、非法坐标、无变化写入和 revision。
- Vue 组件测试：不需要。
- E2E：不需要。

**目标**

以 PRD 和技术方案为准完成最终上线验收，确认 P0 缺陷清零或有明确阻塞记录。

TASK-090、TASK-091、TASK-092、TASK-093、TASK-094、TASK-095、TASK-096、TASK-097、TASK-098、TASK-099、TASK-101。

**本次范围**

- 逐项核对 PRD V1 核心流程和必须功能。
- 核对 MARD 色号、Palette 版本、EMPTY / 白色、统计和导出一致性。
- 核对 P0 bug、自动测试、E2E、构建和静态部署。

**不在本次范围**

- 不把 P1 优化建议或未来能力强行纳入本次验收。
- 不在验收阶段临时增加产品规则或重构架构。

**涉及模块**

全项目、PRD §19～§22、TECHNICAL-DESIGN §19～§21、发布记录。

**产品规则**

PRD §21：稳定可用优先；所有最终颜色属于 MARD 291；编辑器、统计、PNG、PDF 一致；EMPTY 与白色严格区分。

**技术要求**

- 验收基准是同一 Project / Grid / Palette / ExportSnapshot。
- P0 缺陷未清零时不能宣布 V1 完成。
- 任何需求冲突必须报告，不在验收阶段自行改需求。

**验收标准**

1. 主流程：首页 → 上传 → 裁剪 → 64 宽 → 自动高度 → 生成 → 编辑 → 材料 → PNG → PDF 可独立完成。
2. 4:3 + 64 = 64×48，宽度边界 8～256 生效。
3. 两种生成模式均可用且有可感知差异。
4. 单颗改色、删除、全局替换、Undo / Redo 可用。
5. MARD 色号、数量、EMPTY / 白色在所有模块一致。
6. PNG / PDF 可打开、可阅读并可用于制作。
7. 自动测试、E2E、构建、部署和生产冒烟全部通过。
8. P0 bug 清零；遗留问题有负责人、影响和后续安排。

**自动化测试要求**

- 单元测试：全量通过。
- Vue 组件测试：全量通过。
- E2E：主流程、异常流程和生产冒烟通过。

**手动验收建议**

产品负责人使用未参与开发的测试图片独立完成 PRD §21.1 流程，打印 / 预览 PDF，并签收验收清单。

**完成定义**
